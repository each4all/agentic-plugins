# Runtime Follow-ups

ADR-0024 defines more than the first `doctor`, `settings`, consensus, and context scaffold PRs. This file keeps the deferred surfaces explicit so runtime operator commands do not grow into hidden workflow, host-native config, context mutation, or plugin-install mutation by accident.

## Deferred to follow-up PRs

- ADR-0035 §4 active-execution boundary guard — **first slice shipped**: the registry + static test live at `tests/plugin-shape/runtime-executor-registry.mjs`, `runtime-executor-scan.mjs`, and `test-runtime-executor-guard.mjs` (zero-dependency token-aware scan with a comment-stripping/regex-aware tokenizer — not acorn/AST and not a raw grep; `test:` scope, no runtime bump). The hard gate is **runtime-only** (`plugins/runtime/scripts/**/*.mjs`). It is **structurally fail-closed**: a new capability-module import (named/namespace/aliased/dynamic-non-literal/re-export), a process/network primitive, a non-allowlisted or non-literal ("arbitrary") command, or a non-literal argv outside the registry fails the conformance test — including via wrapper aliasing (`const r = runCommand`), namespace member calls (`cp.spawn`/`doctor.runCommand`), and exact-match forwarding exemptions. On top of that structural floor it enforces the §4 ceiling for the shipped surface — `shell:true`/computed/truthy shell option, `sh -c`, dangerous argv verbs via a **per-host-CLI positive verb-path allowlist** (auth bare `login`, `--sandbox`/`danger-full-access`, `hooks trust`, session `resume`/`fork`/`compact`, destructive `remove`/`prune`; `login status` etc. stay allowed), the single permitted retired-plugin `uninstall …@agentic-plugins` template, network GET-only in compat, and external-process kill (only doctor's exact own-child `child.kill('SIGTERM')`). **A new mutating executor (e.g. follow-up C) MUST add its capability import / command / argv verb-path to the registry, or the conformance test fails — the mechanical half of the ADR-0035 §5 add-gate.** Known v1 limitations (covered by the §5 human review, not silently safe): the argv allowlist is **verb-level, not per-call-site** — a new file reusing an already-allowed safe verb (`git init`, `rev-parse`) is not flagged; exotic indirect dispatch (computed-member `obj[name](…)`, deep object indirection) beyond the closed alias/namespace/destructuring/reassignment forms is out of scope; the kill-gate is **receiver-name + signal** (`child.kill('SIGTERM')`), not bound to the exact `runCommand` spawn, so a different `child`-named SIGTERM kill inside the kill-site file would pass; forwarding/projection exemptions are **shape + clean-literal-resolution** heuristics, not full scope analysis; a dynamic/computed shell key via a variable (`const k='shell'; {[k]:true}`) and a regex literal immediately after a brace-less control-flow condition (`if (x) /re/;`) are tokenizer/resolution edges (runtime uses braces and literal keys throughout). Deferred under the same policy: (1) fs-mutation path-scoping (every `writeFile`/`rm`/`rename`/`mkdir` target ⊆ `.agentic-plugins/**`, with the obsolete `~/.codex` `plugin_hooks` write as the known §6 exception); (2) a lighter **repo-wide advisory** sweep for new `child_process`/`fs`/network imports in `companions/`, `plugins/engineer`, and `plugins/orchestrator` (legitimate non-runtime executors today); (3) full argv **taint-tracking** (whether a registered site's variable argv could carry user input) — beyond a zero-dependency static scan.

## Boundaries

- `plugins/companions` remains a script-only library plugin.
- Runtime owns cross-plugin host/runtime truth; it does not become an engineer or orchestrator command bundle.
- Codex plugin-hook feature/trust state and permission limits must stay visible in output instead of being treated as host parity.
- Codex plugin-management command shape and the removed `plugin_hooks` flag (plugin hooks now follow plugin enablement) must stay visible in output as host truth, not collapsed into Claude parity. Codex `0.137.0` per-plugin `add`/`list`/`remove` is recognized (ADR-0032) as the `per-plugin-and-marketplace` surface; output must claim neither a marketplace-only limitation (on `0.137.0`+) nor full Claude parity (`update`/`enable`/`disable`/`details`/`validate`/`prune` remain absent).
- Claude agent teams must not be treated as the portable cross-host team-mode substrate. A portable team-mode design should stay artifacted through runtime/orchestrator consensus, explicit companion dispatch, manual/subagent lanes, and worktree planning unless both hosts expose a compatible team primitive.
- Consensus execution must stay bounded by explicit `--execute`, max rounds, max peers, process budget, and timeout caps. Runtime must not add automatic unbounded loops or relax host permissions.
- Worktree planning must remain read-only unless a future PR adds a separate explicit execution boundary with dry-run defaults.
