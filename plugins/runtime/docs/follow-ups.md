- **The hard-edge closure is host-blind while the selection is not** (peer-surfaced, effective-selection slice). §9.1 states the closure per host — "a selection MUST satisfy every hard edge for every host it targets" — but [`hardRequiredClosure`](../scripts/lib/plugin-set.mjs) walks `hard_requires` ignoring each edge's `hosts`, and [`step-registry.mjs`](../scripts/lib/step-registry.mjs) derives ONE `declinable` flag per plugin from it. - ADR-0035 §4 active-execution boundary guard — **first slice shipped**: the registry + static test live at `tests/plugin-shape/runtime-executor-registry.mjs`, `runtime-executor-scan.mjs`, and `test-runtime-executor-guard.mjs` (zero-dependency token-aware scan with a comment-stripping/regex-aware tokenizer — not acorn/AST and not a raw grep; `test:` scope, no runtime bump). The hard gate is **runtime-only** (`plugins/runtime/scripts/**/*.mjs`). It is **structurally fail-closed**: a new capability-module import (named/namespace/aliased/dynamic-non-literal/re-export), a process/network primitive, a non-allowlisted or non-literal ("arbitrary") command, or a non-literal argv outside the registry fails the conformance test — including via wrapper aliasing (`const r = runCommand`), namespace member calls (`cp.spawn`/`doctor.runCommand`), and exact-match forwarding exemptions. On top of that structural floor it enforces the §4 ceiling for the shipped surface — `shell:true`/computed/truthy shell option, `sh -c`, dangerous argv verbs via a **per-host-CLI positive verb-path allowlist** (auth bare `login`, `--sandbox`/`danger-full-access`, `hooks trust`, session `resume`/`fork`/`compact`, destructive `remove`/`prune`; `login status` etc. stay allowed), the single permitted retired-plugin `uninstall …@agentic-plugins` template, network GET-only in compat, and external-process kill (only doctor's exact own-child `child.kill('SIGTERM')`, plus the registered signal-0 liveness probes in `ALLOWED_PID_LIVENESS_SITES` — `process.kill(pid, 0)` sends no signal and is POSIX's existence check, form-pinned to a literal `0` so a variable or any real signal in the same file still fails; today the sole entry is `bootstrap-artifacts.mjs` stale-lock reclaim, which machine-bootstrap-contract.md §13 fixes as the staleness rule). **A new mutating executor (e.g. follow-up C) MUST add its capability import / command / argv verb-path to the registry, or the conformance test fails — the mechanical half of the ADR-0035 §5 add-gate.** Known v1 limitations (covered by the §5 human review, not silently safe): the argv allowlist is **verb-level, not per-call-site** — a new file reusing an already-allowed safe verb (`git init`, `rev-parse`) is not flagged; exotic indirect dispatch (computed-member `obj[name](…)`, deep object indirection) beyond the closed alias/namespace/destructuring/reassignment forms is out of scope; the kill-gate is **receiver-name + signal** (`child.kill('SIGTERM')`), not bound to the exact `runCommand` spawn, so a different `child`-named SIGTERM kill inside the kill-site file would pass; forwarding/projection exemptions are **shape + clean-literal-resolution** heuristics, not full scope analysis; a dynamic/computed shell key via a variable (`const k='shell'; {[k]:true}`) and a regex literal immediately after a brace-less control-flow condition (`if (x) /re/;`) are tokenizer/resolution edges (runtime uses braces and literal keys throughout). Deferred under the same policy: (1) fs-mutation path-scoping (every `writeFile`/`rm`/`rename`/`mkdir` target ⊆ `.agentic-plugins/**`; the former `~/.codex` `plugin_hooks` write — once the known §6 exception — was removed per ADR-0035 §6, so runtime fs-mutation targets are now agentic-plugins-owned only); (2) a lighter **repo-wide advisory** sweep for new `child_process`/`fs`/network imports in `companions/`, `plugins/engineer`, and `plugins/orchestrator` (legitimate non-runtime executors today); (3) full argv **taint-tracking** (whether a registered site's variable argv could carry user input) — beyond a zero-dependency static scan. **Decision (2026-06-11, runtime:consensus dogfood `consensus-20260611T022143Z-e70631`, converged):** keep all three deferred items **zero-dependency and unbuilt** until a trigger fires — **T1** a real §4-violating pattern reaches `main` past both the guard and the §5 review; **T2** a must-ship executor genuinely needs dynamic argv/path provenance irreducible to fixed templates / registered projections / `.agentic-plugins/**` helper calls, or the registered-exemption set roughly doubles; **T3** closing a new syntax edge needs tokenizer surgery more than once per edge. On a trigger, adopt `acorn`(+`acorn-walk`) as a **tests/-only devDependency** (shipped scripts stay zero-dep); note that AST raises parsing precision but not taint by itself (proper taint still needs custom scope/dataflow). Insight from the run: `verb-level → per-call-site` is a **registry schema** change (add a `file` field to the verb allowlist), not an analysis problem.

## Boundaries

- `plugins/companions` remains a script-only library plugin.
- Runtime owns cross-plugin host/runtime truth; it does not become an engineer or orchestrator command bundle.
- Codex plugin-hook feature/trust state and permission limits must stay visible in output instead of being treated as host parity.
- Codex plugin-management command shape and the removed `plugin_hooks` flag (plugin hooks now follow plugin enablement) must stay visible in output as host truth, not collapsed into Claude parity. Codex `0.137.0` per-plugin `add`/`list`/`remove` is recognized (ADR-0032) as the `per-plugin-and-marketplace` surface; output must claim neither a marketplace-only limitation (on `0.137.0`+) nor full Claude parity (`update`/`enable`/`disable`/`details`/`validate`/`prune` remain absent).
- Claude agent teams must not be treated as the portable cross-host team-mode substrate. A portable team-mode design should stay artifacted through runtime/orchestrator consensus, explicit companion dispatch, manual/subagent lanes, and worktree planning unless both hosts expose a compatible team primitive.
- Consensus execution must stay bounded by explicit `--execute`, max rounds, max peers, process budget, and timeout caps. Runtime must not add automatic unbounded loops or relax host permissions.
- Worktree planning must remain read-only unless a future PR adds a separate explicit execution boundary with dry-run defaults.
